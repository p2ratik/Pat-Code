# BUG REPORT

## Problem 1 :  I have registered and connected a MC server but on clicking sync tools its returning 502 bad gateway error indicating server side issue . 

## Solution:
Root cause — SQLAlchemy async session expiry
Not a user issue. This is a SQLAlchemy async session lifecycle bug.

python
# BEFORE (broken)
async with self.db.get_session() as session:
    server = await self._get_server_by_name(session, server_name)
# ← session CLOSED here. SQLAlchemy marks all ORM object attrs as expired.
is_url_transport = server.transport  # ← DetachedInstanceError / greenlet error
When an async SQLAlchemy session closes, it expires all attributes on ORM objects that were loaded in that session — even with expire_on_commit=False. Accessing .transport, .server_url, or .startup_timeout_sec after the async with block exits causes the exception, which our route catches as a generic Exception and converts to a 502.

python
# AFTER (fixed)
async with self.db.get_session() as session:
    server = await self._get_server_by_name(session, server_name)
    server_url = server.server_url    # ← extracted as plain strings
    transport = server.transport      #    while session is still open
    timeout = server.startup_timeout_sec or 30
# Now use plain variables — no ORM object touched outside the session
The same pattern (_server_to_dict called inside the session, _connection_to_dict called inside the session) is correctly done everywhere else in the service. This one method was the only outlier.

## Problem 2 : 
What was broken
StdioTransport requires:

command = just the executable → "npx"
args = the rest as a list → ["@modelcontextprotocol/server-filesystem", "/path"]
We were storing server_url as a full shell-style string (e.g. "npx @modelcontextprotocol/server-filesystem /home/user/files") and passing the entire string as command="npx @modelcontextprotocol/server-filesystem /home/user/files" with args=[].

The OS then tries to launch a process literally named npx @modelcontextprotocol/server-filesystem /home/user/files — which doesn't exist → process fails → MCPClient.connect() raises → route catches it → 502.

The fix uses shlex.split() (Python's shell-aware tokenizer) to correctly split the stored command string before building MCPServerConfig. This means:

"npx @mcp/server-filesystem /home/user/files"
  → command = "npx"
  → args    = ["@mcp/server-filesystem", "/home/user/files"]
Both discover_and_sync and build_mcp_configs now use this split.

Important: When you register a stdio server in the UI, enter the full shell command in the "Server URL / Command" field (e.g. npx -y @modelcontextprotocol/server-filesystem /path/to/dir). The backend will parse it correctly. For filesystem MCP specifically, make sure to include the directory path as an argument
